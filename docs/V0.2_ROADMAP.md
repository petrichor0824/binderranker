# Protein Design Agent v0.2 Roadmap

本文件记录 v0.1.0 新人冷启动测试发现的问题，以及
`feat/v0.2-agent-core` 分支的整改进度。

状态：

- `[x]` 已完成并通过测试
- `[~]` 已部分完成
- `[ ]` 尚未完成

## P0：新人可用性

### 对话与状态机

- [x] 空 Bundle 的普通问候和产品介绍不再强制进入任务规划
- [x] 使用模型进行语义意图识别
- [x] 用户纠正信息时取消旧 pending action
- [x] pending 状态下允许查看计划
- [x] 支持自然语言查看、复述和解释当前计划
- [x] 批准前自动展示完整计划
- [x] 确定性分析不要求模型调用确认
- [ ] 去除主要流程对固定确认短语的依赖
- [ ] 保留确定性安全层作为最终动作授权边界

### 启动与工作空间

- [x] `pda chat` 可以无额外参数直接启动
- [x] `--bundle-dir` 改为可选并提供安全默认值
- [x] `--approved-by` 改为可选并提供本地默认标识
- [x] 新用户自动创建工作空间和 Bundle
- [ ] 启动后先进行产品介绍和需求理解，而不是立即填写参数

### 数据发现

- [ ] 自动发现用户指定目录中的顶层 PDB
- [ ] 明确默认不递归子目录
- [ ] 支持用户显式要求递归
- [ ] 自动报告文件数量、链布局和异常文件
- [ ] 自动建议 target、binder、design region 和 hotspot
- [ ] 模型建议不得替代用户确认和确定性检查

### 模型配置

- [ ] 提供模型 Provider 选择向导
- [ ] 检查 API Key 环境变量是否存在
- [ ] 区分“网络权限已允许”和“模型连接已验证”
- [ ] 未配置模型时仍允许确定性功能
- [ ] 错误信息明确指出配置、网络或凭据问题

### 结果展示

- [x] BinderRanker 完成后展示确定性 Top 排名预览
- [x] 小样本范围下禁止正式候选推荐
- [x] 自动读取已有结果证据
- [x] 不再要求用户手动粘贴结果 JSON
- [x] 模型解释失败时保留确定性分析
- [x] 模型解释违规时自动修正重试一次
- [ ] 在聊天中展示完整的紧凑结果表
- [ ] 展示每个候选的主要优势和拖累
- [ ] 展示宽松、中等和严格池
- [ ] 候选推荐必须包含确定性 provenance

## P0：错误恢复

- [x] 聊天异常进入统一错误诊断层
- [x] 模型解释错误原因、可能原因和处理建议
- [x] 模型不可用时提供确定性兜底说明
- [x] 脱敏 API Key、Token、Secret 和 Authorization
- [x] 读取最近失败清单
- [x] 读取脱敏后的 stderr 尾部
- [x] 不读取 PDB、完整日志或 Bundle 外文件
- [ ] 区分可安全重试和不可直接重试的错误
- [ ] 明确哪些步骤和产物仍然有效
- [ ] 支持用户确认后只重试失败步骤
- [ ] 不允许模型自动删除、覆盖或绕过批准

## P1：清单与审计

- [ ] 修正 `scientific_workflow_executed` 的提前标记问题
- [ ] 统一准备、批准、执行、分析和解释状态语义
- [ ] 正确聚合 `UNAVAILABLE` 状态
- [ ] 清单记录错误诊断所依据的证据来源
- [ ] 不在审计记录中保存敏感凭据

## P1：示例与发布

- [ ] wheel 包含可运行的最小示例
- [ ] Source ZIP 包含示例数据
- [ ] 示例数据具有来源、版本和用途说明
- [ ] QUICKSTART 从安装到 smoke test 可完整执行
- [ ] 新用户无需知道内部目录结构
- [ ] CI 验证发布包的真实冷启动流程

## P1：科学解释

- [x] 禁止模型修改候选名称、顺序、排名和分数
- [x] 禁止无证据相关性、因果性和显著性声明
- [x] 禁止小样本正式候选推荐
- [x] 允许有限的描述性样本观察
- [ ] 候选选择提供证据支持的推理记录
- [ ] 区分直接评分分量、诊断指标和条件性指标
- [ ] 对模型生成的修复建议建立结构化校验

## P2：代码结构

- [ ] 在功能稳定后拆分过大的对话模块
- [ ] 每次只做小型、可测试的重构
- [ ] 禁止使用字符索引进行大范围源码切割
- [ ] 所有修改先通过 `py_compile`
- [ ] 测试必须使用 `&&` 串联，失败时禁止提交
- [ ] 保留所有已完成 Bundle 和历史结果

## P0：发布产物与路径

- [ ] 用户文档不得要求访问开发仓库中的 `dist/` 目录
- [ ] Release 安装命令直接使用下载后的 wheel 文件名
- [ ] 不假设用户当前工作目录是源码仓库根目录
- [ ] 清除运行时对 `configs/`、`sample_data/`、`runs/` 等仓库相对路径的隐式依赖
- [ ] 区分源码 editable 安装与正式 wheel 安装
- [ ] CI 必须安装真实构建 wheel，而不仅是 `pip install -e`
- [ ] 在仓库外的全新临时目录验证安装和启动
- [ ] wheel 包含运行所需的 BinderRanker 资源
- [ ] wheel 或初始化资源包含可运行的最小示例数据
- [ ] GitHub Source ZIP 包含公开 smoke-test 示例
- [ ] Release 下载后明确提示下一步操作
- [~] `init` 默认可以在当前目录安全初始化
- [ ] 示例命令不得使用 `<项目>` 这类会被 Shell 解释的占位符
- [ ] `doctor` 与真实端到端 smoke test 分开验收
- [ ] CI 验证：安装 wheel → init → chat → smoke test → 结果摘要

## P0：任务与批准隔离

- [x] 批准记录保存在单个 Bundle 内，不是工作空间全局批准
- [x] 批准绑定 prepare manifest、执行计划和数据集指纹
- [x] 执行前重新校验数据集、关键文件和批准摘要
- [x] 统一校验任务名称并安全解析 Bundle 路径
- [ ] 不同 PDB 分组必须创建独立 Bundle
- [~] 默认工作空间支持多个命名任务，而不是长期固定使用 `runs/default`
- [ ] 支持创建、列出、查看和切换当前任务
- [x] 界面始终显示当前任务名称和 Bundle 路径
- [x] A 任务的 pending action 不得影响 B 任务
- [x] A 任务的 approval 不得出现在 B 任务的状态中
- [ ] A 任务失败或未执行时，B 任务仍可独立准备、批准和执行
- [ ] 同一个输入目录包含多个分组时，不得擅自混合排序
- [ ] 自动发现疑似多个数据集时，要求用户选择分组策略
- [x] 大模型把任意目录描述转换为结构化分组建议
- [x] 聊天可根据真实目录证据展示任意数量的分组建议
- [x] 确认分组后为每组创建独立正式规划会话
- [x] 新分组任务只继承输入目录，不复制未确认科学参数
- [ ] 分组数量不得硬编码为 A/B，支持任意数量命名任务
- [~] 确定性扫描器验证每组真实路径、PDB 数量和递归范围
  - [x] MVP：根目录和任意数量直接子目录的顶层 PDB
  - [ ] 后续：复杂递归、多级混合布局和大目录性能优化
- [ ] 检测跨组文件重叠、父子目录包含和遗漏文件
- [ ] 模型建议与真实文件不一致时必须阻止执行并向用户说明
- [ ] 不允许通过覆盖 `planning_session.json` 或 `approval.json` 切换任务

## P2：数据发现增强

- [ ] 支持多级目录和局部递归策略
- [ ] 支持按文件名前缀或清单文件分组
- [ ] 优化超大目录的扫描性能
- [ ] 更完整地处理符号链接和重复真实文件
