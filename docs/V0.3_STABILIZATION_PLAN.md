# BinderRanker v0.3 Stabilization Plan

## Purpose

Post-release stabilization based on first-time external user testing.

## Current Status

BinderRanker v0.3.0 has completed:

- public release workflow
- package distribution
- clean installation validation
- deterministic ranking workflow
- approval and execution safety boundaries

## User Acceptance Findings

### UX Issues

- First-time users do not know whether to run init.
- Chat entry does not clearly guide first workflow.
- Task state transitions are too exposed.
- Multiple confirmations make simple smoke tests cumbersome.
- Error messages expose internal state machine concepts.

### Agent Issues

- Conversation context recovery needs improvement.
- Planning flow is too rigid.
- Natural language requests are not always mapped to valid next actions.

## v0.3.1 User Experience Stabilization

Priority:

1. First-run onboarding.
2. Automatic workspace initialization guidance.
3. Natural language task intake.
4. Simplified confirmation flow.

### 5. Conversation context summary

Goals:

- Preserve task history across sessions.
- Restore previous task state with user-friendly explanations.
- Separate conversation memory from deterministic task state.

### 6. User-facing error translation

Goals:

- Hide unnecessary internal state machine details.
- Explain what happened, why it happened, and the next recommended action.

### 7. Guided first workflow

Goals:

Provide a complete first-run path:

install
→ initialize workspace
→ extract sample data
→ inspect PDB
→ prepare task
→ approve
→ execute
→ analyze results

## Explicit Non-goals

The stabilization phase will not:

- Replace BinderRanker deterministic core.
- Redesign scientific scoring methodology.
- Expose unpublished calibration parameters.
- Expand Agent features before runtime architecture migration.

## v0.3.2 Scientific Transparency

Priority:

1. Explain metric definitions.
2. Provide score decomposition.
3. Separate public methodology from unpublished calibration details.

Goals:

- Make ranking evidence understandable without exposing unpublished calibration choices.
- Allow users to understand why candidates rank differently.

## v0.4 Agent Runtime Migration

Goals:

- Introduce modern Agent runtime architecture.
- Keep BinderRanker deterministic core unchanged.
- Use Tool API as stable boundary.
- Improve planning, memory, and tool orchestration.
- Migrate Agent orchestration without changing scientific execution semantics.
